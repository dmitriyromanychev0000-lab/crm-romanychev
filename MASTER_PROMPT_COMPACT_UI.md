# Мастер-промпт: компактный UI + баг наложения модалки

## Контекст
Визуальный источник истины — `Visual_koncept/` (10 PNG-концептов) уже в
репозитории, см. `Visual_koncept/README.md` и `WORK_START_HERE.md`. Работай
по ним экран за экраном, не переписывай CSS одним махом.

**Важно:** этот промпт написан после ручного анализа скриншотов
Claude (у Claude есть зрение, у текущей серверной модели — нет, поэтому
финальная доводка идёт через тебя). Числа ниже — ориентир по пропорциям
из концептов, не догма: сверяйся с картинками, если что-то не совпадает.

## Задача 1 — компактность полей и кнопок (в работе, доведи до конца)

Уже применено в базовых классах (`.field`, `.search`, `.icon-button` /
`.primary-button` / `.secondary-button` / `.danger-button`,
`.search-with-icon .search`):
- высота полей/кнопок: было 50-68px → стало ~44-46px
- шрифт: было 16-18px → стало ~15px
- border-radius: было 17-22px → стало ~14px
- padding сужен пропорционально

**Осталось:** в файле ещё ~190 своих min-height/font-size под конкретные
экраны и `@media`-брейкпоинты (многие уже компактные, часть — нет).
Пройдись по ключевым экранам из `Visual_koncept/` (в порядке листов 01-10)
и сверь каждое поле/кнопку с картинкой: где раздуто относительно концепта —
ужми до той же пропорции, что и в базовых классах выше. Не трогай то, что
уже соответствует концепту.

Особое внимание — модалка редактирования позиции услуги/материала
(скрин "Ремонт платы" с полями `Кол-во` / `Ед.` / `Списание"`): сейчас
три поля в ряд разной ширины, текст в дропдауне обрезан ("Отметь..."
вместо полного слова). Сделай три поля равномерной сеткой
(`grid-template-columns: repeat(3, 1fr)` или похоже), с одинаковой высотой,
текст в дропдауне должен помещаться целиком или иметь `text-overflow`
по всей ширине, а не обрезаться на 5 символах.

## Задача 2 — баг наложения контента под модалкой (НАЙДИ И ПОЧИНИ, приоритет выше задачи 1)

При открытии модалки (пример: экран заявки, выбор услуг) на скриншоте
видно, что элементы СПИСКА ПОД модалкой продолжают быть видны/читаемы
сквозь затемнение — текст, суммы, чекбоксы накладываются друг на друга
("призрачный" эффект, будто два слоя контента рендерятся одновременно
в одном месте).

В `styles.css` пять разных переопределений `.modal-backdrop` под разные
`@media`-брейкпоинты (строки ~1180, ~2827, ~3068, ~3506, ~3710 в текущей
версии — могли сместиться после правок, ищи по селектору). У них разные
`top`/`bottom`/`background` значения. Похоже, на реальной ширине экрана
пользователя срабатывает не то правило, или фон недостаточно непрозрачен,
или блок под модалкой не получает `overflow: hidden` / модалка не
перекрывает его целиком по высоте.

Проверь на реальном телефоне (или в devtools с эмуляцией мобильного
разрешения ~390-430px) — открой любую модалку поверх длинного списка,
убедись что фон списка НЕ просвечивает и не воспринимает клики/скролл
одновременно с модалкой.

## Правила работы (уже были в WORK_START_HERE.md, повторяю явно)

- Один экран за раз, проверка на реальном телефоне перед следующим.
- Не убирай рабочий функционал ради красоты.
- Коммить маленькими последовательными коммитами.
- Если текст на макете искажён (артефакт генерации картинки) — бери текст
  из текущего кода CRM, макет — только про layout/размеры/цвета.
